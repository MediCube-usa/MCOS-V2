# MCOS V2 Site Shell And Navigation

## Purpose

Define the global MCOS V2 interface shell before individual pages are built.

MCOS V2 is a private company operating dashboard. It should help Jordan and internal operators see the business, machines, work, messages, inventory, setup, documents, finance, vouchers, and field execution from one system.

## Global Layout

The site has:

- persistent left sidebar
- top communication bar
- main page workspace
- Command Center as the main landing page
- page-specific department dashboards
- agent presence by page where useful

## Sidebar Behavior

Sidebar tabs run down the side and remain consistent across all pages.

Each sidebar tab opens the matching department page. Each Command Center block links to the same destination.

The sidebar should not be redesigned page by page.

## Top Communication Bar

The top bar is not a generic search header.

It should behave like a small company communication dashboard.

It should include:

- company email/messages
- support/info messages
- phone/customer messages when connected
- Google Calendar or company calendar
- upcoming meetings
- Zoom or Google Meet links
- machine arrivals
- restocks
- product shipments
- setup appointments
- reminders
- urgent operating items

The top bar is for Jordan, partner, and internal operators to stay connected to the company while working inside MCOS.

## Command Center Block Rule

Every major page gets a Command Center block.

Each block should:

- show what matters most for that department
- show urgent issues
- show open tasks
- show progress
- link to the matching sidebar tab
- avoid duplicating the full page
- avoid invented data
- summarize from the connected source of truth

## Agent Model

Agents use central MCOS data and workflow permissions.

Agent levels:

- Command Center Agent: higher-clearance executive supervisor
- Page Agents: department-specific workers
- Central data hub: shared source all agents use
